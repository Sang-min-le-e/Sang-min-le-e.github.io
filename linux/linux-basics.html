리눅스 구조: 커널과 셸

이 개념을 한 문장으로. 비유가 있으면 더 좋다.

작성 가이드 (다 쓰면 이 상자들은 지우기). 강의 1–2강 범위. 비유 후보: 셸 = 커널을 감싼 '껍데기'(2강).

01개념

무엇인가

무엇을 정의할지. 아래 셋을 각각 한두 문장으로.
  • 운영체제와 커널, 그리고 둘의 포함 관계
  • 셸: 사용자와 커널 사이에서 하는 일
  • 그래서 "리눅스"는 정확히 무엇을 가리키는지, GNU/Linux라는 이름

왜 필요한가

이게 없으면 어떤 문제가 생기는지부터.

무엇을 쓸지. "만약 ~이 없다면"으로 시작해 보기.
  • 커널이 없다면: 프로그램마다 키보드, 디스크 같은 하드웨어를 직접 다뤄야 한다면? (2강 1번: 장치 드라이버, 프로세스·파일·보안 관리)
  • 셸이 없다면: 사용자가 커널에 직접 명령해야 한다면? (2강 2번: 명령어 해석기)
  • 셸이 여러 종류인 이유: sh → csh, ksh → bash로 기능이 보완된 흐름 (2강 3, 4번)

02직접 해보기

Lab · 명령어 한 줄이 하드웨어까지 가는 길
명령어를 입력하고 실행을 누르면, 명령이 어느 층을 지나가는지 한 단계씩 보여 줍니다.

위가 사용자, 아래가 하드웨어. 파랗게 켜진 층이 지금 일하는 곳.

실험해 볼 것

  • 실행을 눌러 명령이 셸 → 커널 → 하드웨어로 내려갔다가, 결과가 다시 위로 올라오는 순서 보기.
  • 오타 내기를 눌러 명령이 어느 층에서 멈추는지, 커널까지 가는지 보기.
  • 운영체제 범위와 "리눅스" 범위를 번갈아 눌러, 흔한 오해(리눅스 = 운영체제)가 어디서 생기는지 보기.

내 터미널에서 해 보기

강의 2강에서 직접 보여 준 실습이다.

  1. cat /etc/shells로 지금 시스템에 설치된 셸 목록을 본다.
  2. bash에서 ls를 치면 디렉토리와 파일이 색상으로 구분된다. 이름 일부만 치고 Tab을 누르면 자동 완성된다.
  3. sh를 입력해 본 셸로 바꾼 뒤 같은 ls를 치면 색상 구분이 없고, Tab을 누르면 공백만 찍힌다. exit로 bash에 돌아온다.
